# Synthetic Reimbursement Guide

> **Academic demo only.** This guide is invented for COMP6708 and is **not** an official PolyU reimbursement policy.

## Demo information to collect

A reimbursement request should contain:

- a short description of the expense;
- an activity code used by the course demo;
- one or more expense lines;
- the amount and currency for each line; and
- supporting evidence for each claimed expense.

## Demo supporting evidence

Each reimbursement line should normally have a receipt or equivalent supporting document in the prototype. If a document is missing, the user should explain the situation in the request notes rather than inventing evidence.

## Demo workflow

A reimbursement can move from Draft to Submitted. Finance may return it for more information. The user can update and resubmit a returned request. A processed reimbursement can eventually reach Completed.

## Assistant behaviour

The demo assistant may summarize these requirements. It must not promise approval, payment timing, eligibility, tax treatment, or any real university entitlement.
